# 멀티 디바이스 로그 수집 — 화면 UI 계획

작성 2026-10-23 · 브랜치 `multi-device`

PC 1대에 Android 폰 여러 대를 **Wi-Fi 와 USB 로** 붙여 **기기마다 LogCat 을 계속 받아 설정한
주기마다 파일로 저장**한다. 그중 한 대를 골라 지금처럼 미러링하고 실시간 로그를 본다. 두 방식으로
연결된 기기가 한 목록에 같이 뜬다.

## 구현 현황 (2026-10-23)

**1~3단계 구현.** 4단계(페어링 UI · mDNS 자동 발견 · 배터리)는 선택 항목이라 아직 없다.

| 위치 | 내용 |
|---|---|
| `src/device-hub.js` | 기기 감시·합치기·저장·파일 분할·재연결·포트 복구. 자가진단 `node src/device-hub.js` (가짜 adb 로 꽂기 → 합치기 → 넘어가기 → 복구 → 재시작 후 이어 받기 → 보관 정리까지 68개) |
| `main.js` · `preload.js` | `device:*` IPC, `device:update` 푸시 |
| `index.html` · `style.css` · `renderer.js` | 오른쪽 패널 탭·바둑판, 기기 전환, 설정 탭 'LogCat 자동 저장' 카드 |

계획에서 바뀐 것

- 기억해 둔 Wi-Fi 주소와 저장 설정은 `localStorage` 가 아니라 **`userData/multi-device.json`** 에 둔다.
  재연결을 메인 프로세스가 맡아서, 화면이 뜨기 전에도 읽어야 한다.
- **새로 연결한 기기는 저장이 꺼진 채로 시작한다** (사용자 요청). 기기마다 카드의 ● 로 켜고, 그 값은
  `deviceRec` 에 기기 id 별로 기억한다. 설정 탭의 '새로 연결한 기기 바로 저장'(`autoNew`, 기본 끔)이
  고른 적 없는 기기의 기본값이다.

**실기기로 확인한 것 (SM-G973N Wi-Fi + SM-S926N USB, 2026-10-23)**

- USB·Wi-Fi 기기가 한 바둑판에 같이 뜨고 둘 다 실시간 저장됨. 52만 줄 중 다른 시간 파일로 간 줄 0.
- Wi-Fi 기기도 `ip:port` 가 아니라 `ro.serialno` 폴더로 저장됨.
- 앱 재시작 후 `logcat -T '<시각>'` 이어 받기 동작 — 공백이 든 인자도 adb 가 제대로 넘긴다. 경계 시각의
  한 줄만 겹치고(`-T` 는 그 시각을 포함) 빠진 줄은 없음.
- 기기별 저장 끄기 → 저장용 logcat 만 내려가고 화면 LogCat 은 그대로.
- **기기 전환 중 미러링이 겹치던 버그를 실기기에서 겪고 고침** — 시작이 끝나기 전에 다른 시작이 끼어들어
  서버가 두 개 뜨고, 지난 세션의 늦은 웹소켓 닫힘이 새 화면을 지웠다. 메인(`inMirrorQueue`)과
  렌더러(`queueDeviceOp`, `mirrorSession`) 양쪽에서 줄을 세워 막았다. 해제 직후 재선택 시험에서 중지 1번 →
  시작 1번으로 깔끔하게 이어짐을 확인.
- 두 대 사이 빠른 전환 (SM-G973N → SM-S926N → SM-G973N, 0.5초 간격 클릭) — 시작 중에 들어온 클릭은 줄에서
  기다렸다가 차례로 처리되고, 브리지의 시작(`STEP 1`)은 매번 앞 세션이 스트리밍까지 끝나고 멈춘 뒤에만
  나왔다. 마지막 클릭한 기기가 최종 화면.
- 새로 연결한 기기는 저장 꺼짐으로 뜨고(카드 "저장 꺼짐 · 오른쪽 위 ● 로 켜기"), 저장용 logcat 은 0개.

**실기기로 아직 확인하지 못한 것** — 기기를 붙여 놓고 볼 것

- 다른 기종에서 `-T` 인자가 거부되는 경우 — 그러면 `-T` 로 시작한 저장이 곧바로 끝나는데, 두 번 이어지면
  그 기기는 이어 받기 없이 처음부터 받는다(`[멀티] … 이어 받기(-T)가 거부되어` 로그).
- `adb reconnect offline` 이 정상 기기를 건드리지 않는지.
- 연결 시간 초과(`10060`) 문구 — 연결 거부(`10061`)만 실측했다.
- USB 로 꽂힌 폰의 `tcpip 5555` → `adb connect` 전환과, 재부팅 후 USB 로 꽂았을 때의 자동 복구.
- 같은 폰의 USB 시리얼과 `ro.serialno` 가 다른 기종에서 카드가 제대로 한 장으로 합쳐지는지.

## 가능 여부 — 가능하다

| 항목 | 판단 | 근거 |
|---|---|---|
| 여러 대 동시 연결 | 가능 | adb 는 시리얼(`-s`)로 기기를 구분한다. USB 기기는 기기 시리얼, Wi-Fi 기기는 `ip:port` 가 시리얼이 된다. 섞어서 붙여도 된다 |
| 기기별 LogCat 동시 수집 | 가능 | 기기마다 `adb -s <시리얼> logcat` 프로세스를 하나씩 띄운다. 이 프로젝트에서 잰 SM-G973N 이 초당 약 19줄이라 기기당 초당 수 KB — PC·네트워크 부담은 작다 |
| 주기별 파일 저장 | 가능 | 메인 프로세스가 스트림을 파일에 바로 쓰고, 주기가 되면 새 파일로 넘긴다 |
| 동시 미러링 | **1대만** | 영상 디코딩은 기기당 부담이 커서 고른 1대만 미러링한다 (지금 구조 그대로) |

### Wi-Fi 라서 생기는 제약 — 설계에 반드시 반영

- **끊긴다.** 화면 꺼짐·절전·공유기 문제로 adb 연결이 떨어진다. 자동 재연결이 필수다
  ([끊김 상태별 처리](#끊김-상태별-처리--usbwi-fi-공통)).
- **Android 11+ 무선 디버깅은 포트가 바뀐다.** 재부팅하거나 무선 디버깅을 껐다 켜면 연결 포트가
  새로 정해지고, PC 마다 최초 1회 `adb pair` 가 필요하다.
  - 새 포트는 mDNS 자동 발견(`adb mdns services`)으로 찾는다. 이 PC 의 adb 37 에서 명령 동작은
    확인했고, **실제 기기로는 아직 검증하지 않았다.**
  - 대안: 포트를 5555 로 고정한다 → [Wi-Fi 주소 고정](#wi-fi-주소-고정--ip-와-포트).
- **끊긴 동안의 로그는 기기 버퍼에 남은 만큼만 되살릴 수 있다.** 재연결하면 마지막으로 받은 시각부터
  이어 받는다(`logcat -T '<시각>'`). 버퍼(기기마다 수백 KB~수 MB)보다 오래 끊기면 공백이 생긴다.
  연결할 때 버퍼를 키우는 옵션(`logcat -G 16M`)을 검토한다 — 기기마다 허용 여부가 달라 미검증.
- **용량.** 초당 19줄 × 줄당 약 150B 로 잡으면 기기당 시간당 약 10MB, 하루 약 250MB. 10대면 하루
  2.5GB 라 보관 기간 설정이 필요하다.
  - **실측 (2026-10-23, 10:00~10:49 파일 기준)**: SM-G973N 초당 24.8줄 · 시간당 약 11.5MB, SM-S926N
    초당 44.5줄 · 시간당 약 23MB(하루 약 550MB). **기종마다 2배 넘게 차이 난다** — 최신 기종이 많으면
    10대에 하루 3~6GB, 보관 7일이면 20~40GB 를 잡아야 한다.
  - 처음 붙을 때 기기 버퍼에 남은 로그부터 받으므로 첫 파일이 크다 (SM-G973N 은 자정부터 32MB 가 한 번에 들어왔다).

### Wi-Fi 주소 고정 — IP 와 포트

**둘 다 고정할 수 있다. 다만 고정하는 곳이 다르고, 포트는 재부팅하면 풀린다.**

| | 고정하는 곳 | 유지 기간 |
|---|---|---|
| IP | 공유기의 DHCP 예약(권장) 또는 폰의 고정 IP 설정 — 앱이 바꿀 수 없다 | 계속 |
| 포트 | `adb -s <시리얼> tcpip 5555` — 앱이 대신 실행한다 | **재부팅 전까지** |

**IP**

- 공유기 관리 페이지에서 폰의 MAC 주소에 IP 를 예약해 두는 방법을 권한다. 폰마다 설정할 것이 없고
  IP 충돌도 없다.
- 주의: Android 10 이상은 Wi-Fi 마다 **무작위 MAC** 을 쓰는 것이 기본이다. 네트워크를 지웠다 다시 잡는
  등으로 MAC 이 바뀌면 예약이 빗나간다. 폰의 그 Wi-Fi 설정에서 MAC 주소 유형을 **휴대전화 MAC** 으로
  바꿔 두면 확실하다 (삼성: Wi-Fi → 연결된 네트워크 ⚙ → 고급 → MAC 주소 유형).
- 공유기를 만질 수 없으면 폰에서 고정 IP 를 줄 수 있다 (Wi-Fi 네트워크 설정 → IP 설정 → 고정). 이때는
  공유기가 자동으로 나눠 주는 범위 밖의 주소를 써야 다른 기기와 겹치지 않는다.

**포트**

- `adb tcpip 5555` 를 한 번 실행하면 기기가 5555 포트로 접속을 받는다. Android 버전과 무관하고 페어링도
  필요 없다.
- **재부팅하면 풀린다.** 일반 폰(루팅 안 함)에서는 재부팅 후까지 유지할 방법이 없다.
- Android 11+ 의 무선 디버깅은 켤 때마다 포트가 바뀌어 그 자체로는 고정할 수 없다. 대신 무선 디버깅으로
  한 번 붙은 뒤 `tcpip 5555` 를 실행하면 그때부터 5555 로 고정된다 — USB 없이 가능, 실기기로는 미검증.
- `tcpip 5555` 를 실행하는 순간 그 기기의 adb 가 재시작되어 연결이 잠깐 끊긴다. 로그는 이어 받기로 메운다.

**재부팅으로 풀린 포트를 앱이 되살리는 흐름**

1. 기기마다 고정 주소(`IP:5555`)를 기억해 두고 항상 그 주소로 붙는다.
2. 연결이 안 되면 오류 종류로 원인을 가른다.
   - **연결 거부** — 폰은 네트워크에 있는데 5555 가 닫혀 있다 → 재부팅으로 포트가 풀렸다고 본다. 카드에
     "USB 를 한 번 꽂거나 무선 디버깅을 켜 주세요" 를 띄운다.
   - **시간 초과** — 폰이 네트워크에 없다(꺼짐·Wi-Fi 끊김·범위 밖) → 계속 재시도한다.
3. 그 폰이 USB 로 꽂히거나 무선 디버깅으로 발견되면(mDNS) **앱이 알아서 `tcpip 5555` 를 실행하고 고정
   주소로 다시 붙는다.** 사용자는 꽂았다 뽑기만 하면 된다.

오류는 **문구가 아니라 오류 코드로** 가른다. Windows 에서는 문구가 한글로 나온다 — 이 PC 에서 실측:
`cannot connect to 127.0.0.1:5599: 대상 컴퓨터에서 연결을 거부했으므로 연결하지 못했습니다. (10061)`.
연결 거부는 `10061`, 시간 초과는 `10060` 이다 (Windows 소켓 오류 코드, `10060` 은 아직 실측 전).
macOS 는 영문 `Connection refused` / `timed out` 으로 나오므로 둘 다 본다.

이 흐름의 핵심이 USB 로 꽂혔을 때의 자동 전환이라, 처음에 4단계로 잡았던 **"Wi-Fi 로 전환"을 1단계로 당긴다.**

### USB 로 연결한 기기

- **꽂으면 자동으로 목록에 뜬다.** 지금도 5초마다 `adb devices` 를 돌려 기기를 찾고 있으므로
  (`runSetupCheck()`) 그 결과를 바둑판에 그대로 쓴다. USB 기기는 '기기 추가'를 거칠 필요가 없다.
- **연결 방식은 시리얼 모양으로 구분한다.** Wi-Fi 기기의 시리얼은 `192.168.0.12:5555` 같은 `IP:포트`
  이거나, mDNS 로 붙은 경우 `adb-<시리얼>-xxxx._adb-tls-connect._tcp` 형태다. 둘 다 아니면 USB 다.
  `adb devices -l` 의 `usb:` 항목은 Windows 에서 나오지 않을 수 있어 기대지 않는다 (미확인 — 기기를
  꽂고 한 번 확인할 것).
- **USB 도 끊기는 모양이 두 가지다.** 목록에서 **사라지면** 케이블을 뽑은 것이라 다시 꽂히기를
  기다린다. 목록에 **그대로 있는데 `offline`** 이면 기기는 잡혀 있고 연결만 꼬인 것이라 PC 쪽에서
  재연결을 시도할 수 있다 — 아래 [끊김 상태별 처리](#끊김-상태별-처리--usbwi-fi-공통).
- **같은 폰이 두 번 잡힐 수 있다.** USB 로 꽂아 둔 채 Wi-Fi 연결도 켜면(예: `adb tcpip 5555` 후 케이블을
  안 뽑은 경우) adb 목록에 USB 시리얼과 `ip:port` 로 따로 뜬다. 그대로 두면 카드가 2장이 되고 **로그도
  이중으로 저장된다.**
  - 기기의 `ro.serialno` 로 **한 장으로 합치고**, 로그 프로세스도 기기당 하나만 둔다. 둘 다 살아 있으면
    더 안정적인 USB 로 받는다.
  - 케이블을 뽑으면 Wi-Fi 로 **자동으로 넘어가** 마지막 시각부터 이어 받는다. 반대로 Wi-Fi 가 끊겨도
    USB 가 살아 있으면 그쪽으로 넘어간다. 넘어갈 때 말고는 일부러 바꾸지 않는다(오가며 흔들리지 않게).
- **Windows 는 제조사 USB 드라이버가 있어야 인식된다** (삼성은 Samsung USB Driver). 이 PC 는 이미
  설치돼 있어 SM-G973N 이 잡힌다. 다른 PC 에 배포할 때 안내가 필요하다.
- 여러 대를 꽂으면 포트 수와 전원이 모자란다 — **전원 공급형 USB 허브**를 권한다. USB 기기는 충전이
  같이 되니 장시간 수집에는 오히려 Wi-Fi 보다 유리하다.

### 끊김 상태별 처리 — USB·Wi-Fi 공통

연결 방식이 아니라 **adb 목록에 나타난 상태**로 판단한다. 이 PC 의 adb 37 도움말에서 재연결 명령
세 가지(`reconnect` / `reconnect device` / `reconnect offline`)를 확인했다.

| adb 목록의 상태 | USB | Wi-Fi |
|---|---|---|
| `device` | 정상 | 정상 |
| `offline` (목록에는 있음) | 재연결 시도 ①→②→③ | 재연결 시도 ①→②→③, 그래도 안 되면 ④ |
| `unauthorized` | 폰에서 "USB 디버깅 허용"을 누르기를 기다린다 | 같음 |
| 목록에서 사라짐 | 케이블 뽑힘 — 다시 꽂히기를 기다린다 | `adb connect` 를 주기적으로 재시도 |

- ① `adb -s <시리얼> reconnect` — PC 쪽에서 끊었다 다시 붙인다
- ② `adb -s <시리얼> reconnect device` — 기기 쪽에서 끊었다 다시 붙인다
- ③ `adb reconnect offline` — `offline`·`unauthorized` 기기만 골라 다시 붙인다
- ④ `adb disconnect <ip:port>` 후 `adb connect <ip:port>`

- 시도 간격은 점점 늘린다 (5초 → 10초 → 30초 → 1분에서 고정). 10분 넘게 복구되지 않으면 카드를
  '복구 실패'로 바꾸고, USB 면 "케이블을 다시 꽂아 보세요" 를 안내한다. 그 뒤에도 1분 간격 재시도는 계속한다.
- 복구되면 마지막으로 받은 시각부터 로그를 이어 받는다(`logcat -T`).
- **`adb kill-server` 는 자동으로 쓰지 않는다.** adb 서버를 내리면 **모든 기기 연결이 한꺼번에 끊겨**
  멀쩡한 기기의 저장까지 멈추고, Wi-Fi 기기는 `adb connect` 부터 다시 해야 한다. 정말 필요하면 설정 탭의
  수동 버튼(`adb 전체 재시작`)으로만 둔다.
- ③ 이 정상 기기를 건드리지 않는다는 건 도움말 문구 기준이다 — 여러 대를 붙여 놓고 실제로 확인할 것.
- 일부러 `offline` 을 만들어 시험하는 방법: 폰의 개발자 옵션에서 USB 디버깅을 껐다 켠다.

## 지금 코드에서 막히는 곳

| 지점 | 지금 | 바뀌어야 할 것 |
|---|---|---|
| `main.js` `logcatProcess` | 전역 1개. 새로 시작하면 이전 것을 죽인다 | 기기별 프로세스 + 파일 쓰기 |
| `main.js` `adb:devices` | `device` 상태만 돌려준다 — 끊긴 기기는 목록에서 사라진다. USB 인지 Wi-Fi 인지도 알려주지 않는다 | `offline` / `unauthorized` 도 상태로, 연결 방식(시리얼 모양으로 판별)도 같이 돌려준다 |
| 같은 기기 중복 | 구분하지 않는다 | `ro.serialno` 로 USB·Wi-Fi 항목을 한 기기로 합친다 |
| `renderer.js` `selectDevice()` → `setConnected()` | 이미 미러링 중이면 새 기기로 바꾸지 않는다(`if (!state.mirroring)`) | 기존 미러링 정지 → 새 기기로 시작 |
| `renderer.js` `connectWifi()` | 모델명 대신 IP 를 이름으로 쓴다 | 연결 후 모델명을 조회해 카드에 표시 |
| 크래시·ANR 감지 | 렌더러가 **보고 있는 기기** 스트림에서만 감지 | 모든 기기 배지를 위해 메인으로 옮긴다 |

## 제안하신 방식에 대한 의견

> 미러링 오른쪽 로그 영역 자리에 연결된 기기를 바둑판으로 → 카드를 누르면 미러링에 연결 →
> 바둑판이 사라지고 로그 영역이 나온다

방향은 좋다. 오른쪽 패널이 최소 720px 라 카드 3열이 자연스럽게 들어가고, 미러링 영역은 그대로
둘 수 있다. 다만 그대로 만들면 네 가지가 빈다.

1. **돌아갈 길이 없다.** 바둑판이 사라진 뒤 다른 기기로 바꾸려면 어디로 가야 하나.
2. **다른 기기 상황이 안 보인다.** 한 대를 보는 동안 다른 폰이 끊겼는지, 저장이 멈췄는지, 크래시가
   났는지 알 수 없다. 여러 대를 돌리는 이유가 바로 그걸 놓치지 않기 위해서다.
3. **'보기'와 '저장'이 섞인다.** 로그 영역은 고른 1대만 보여주지만 저장은 모든 기기에서 계속 돌아야 한다.
4. **끊김이 일상이다.** Wi-Fi 특성상 카드마다 연결 상태가 보여야 한다.

## 제안 — 같은 자리에서 탭으로 전환

오른쪽 패널 맨 위에 탭 두 개를 둔다. 바둑판은 사라지는 게 아니라 **탭 뒤로 물러난다.**
카드를 누르면 제안하신 대로 LogCat 탭으로 자동으로 넘어가고, 언제든 기기 탭으로 돌아올 수 있다.

### 기기 탭

```
┌ 도구 패널 ┐┌ 미러링 ┐┌─────────────── 오른쪽 패널 ───────────────┐
│           ││        ││  [ 기기 6대  ⚠ 2 ]   [ LogCat · G973N ]     │ ← 탭
│           ││        ││ ┌────────────┐┌────────────┐┌────────────┐ │
│           ││        ││ │● SM-G973N  ││● Galaxy A52││⟳ SM-G991N  │ │
│           ││ (선택한 ││ │USB         ││Wi-Fi .15   ││재연결 중 3분│ │
│           ││  기기)  ││ │저장 중 84MB││저장 중 12MB││            │ │
│           ││        ││ └────────────┘└────────────┘└────────────┘ │
│           ││        ││ ┌────────────┐┌────────────┐┌────────────┐ │
│           ││        ││ │● Pixel 7   ││⚠ Note 20   ││     +      │ │
│           ││        ││ │USB + Wi-Fi ││USB         ││  기기 추가  │ │
│           ││        ││ │크래시 2    ││인증 필요   ││  (Wi-Fi)   │ │
│           ││        ││ └────────────┘└────────────┘└────────────┘ │
└───────────┘└────────┘└────────────────────────────────────────────┘
```

- **USB 와 Wi-Fi 기기가 한 바둑판에 섞여 뜬다.** 카드 둘째 줄이 연결 방식이다. 같은 폰이 둘 다로
  붙어 있으면 카드는 한 장이고 `USB + Wi-Fi` 로 표시한다.
- 탭의 `⚠ 2` 는 **문제 있는 기기 수**(끊김·인증 필요·크래시). LogCat 탭을 보고 있어도 눈에 띈다.
- 지금 미러링 중인 기기 카드는 테두리를 강조한다.
- LogCat 탭 이름에 **어느 기기 로그인지** 붙인다 — 여러 대일 때 헷갈리지 않게.

### 카드

| 줄 | 내용 | 이유 |
|---|---|---|
| 1 | 상태 점 + 모델명 | 누구인지 |
| 2 | 연결 방식 — `USB` / `Wi-Fi 192.168.0.12` / `USB + Wi-Fi` | 어디로 붙어 있는지, 같은 모델이 여러 대일 때 구분 |
| 3 | 저장 상태 — `● 저장 중 · 오늘 84MB · 3초 전` | 저장이 실제로 되고 있는지 |
| 4 | 배지 — `크래시 2 · ANR 1` (오늘) | 여러 대 중 문제 난 폰을 바로 찾기 |

| 상태 | 표시 | 카드를 누르면 |
|---|---|---|
| 연결됨 | 초록 점 | 미러링 + LogCat 탭으로 |
| 재연결 중 (`offline`, 또는 Wi-Fi 가 목록에서 사라짐) | 노란 회전 아이콘 + 경과 시간 | "재연결 중" 안내 |
| 케이블 뽑힘 (USB 가 목록에서 사라짐) | 회색 `연결 대기` | "다시 꽂으면 이어서 받습니다" 안내 |
| 인증 필요 (`unauthorized`) | 주황 ⚠ | 폰에서 "USB 디버깅 허용" 안내 |
| 포트 풀림 (고정 주소 연결 거부 — 재부팅 추정) | 주황 ⚠ | "USB 를 한 번 꽂거나 무선 디버깅을 켜 주세요" 안내 |
| 복구 실패 (10분 넘게 재시도) | 회색 | 바로 다시 시도. USB 면 "케이블을 다시 꽂아 보세요" 안내 |

카드 오른쪽 위 `⋯` 메뉴: 저장 켜기/끄기 · 로그 폴더 열기 · 목록에서 제거 · (USB 카드) Wi-Fi 로 전환.

### 흐름

1. 앱 시작 → USB 기기는 바로 뜨고, Wi-Fi 기기는 기억해 둔 주소로 자동 재연결 → 오른쪽은 **기기 탭**,
   미러링 영역은 "기기를 선택하세요"
2. 카드 클릭 → 미러링 영역에 그 기기 연결 + 오른쪽이 **LogCat 탭**으로 자동 전환
3. 다른 기기로 바꿀 때: 기기 탭 → 카드 클릭. 기존 미러링은 자동으로 멈추고 새 기기로 시작
4. 저장을 켠 기기는 무엇을 보고 있든 **계속 저장된다**. 새로 연결한 기기는 저장이 꺼진 채로 뜨고, 카드의
   ● 로 기기마다 켠다 (2026-10-23 요청으로 기본값을 '꺼짐'으로 바꿈)

### 기기 추가

- **USB 기기는 꽂으면 저절로 뜬다.** 따로 추가할 것이 없다.
- 바둑판 마지막 칸 `+ 기기 추가` 는 Wi-Fi 기기용이다 → 지금의 기기 연결 팝업의 Wi-Fi 탭을 그대로 쓴다.
  입력한 IP·포트(기본 5555)를 그 기기의 **고정 주소로 기억**한다
- 한 번 연결한 Wi-Fi 기기는 기억해서 앱을 다시 켜면 자동 재연결 (`userData/multi-device.json`)
- **USB 카드의 `Wi-Fi 로 전환`** — PC 가 `adb tcpip 5555` → 기기 IP 조회 → `adb connect` 까지 대신
  해 주고, 그 주소를 고정 주소로 기억한다. 여러 대를 Wi-Fi 로 세팅할 때 **한 대씩 꽂았다 뽑기만** 하면
  된다. 재부팅으로 포트가 풀린 기기가 USB 로 꽂히면 같은 일을 자동으로 한다 — 1단계
  ([Wi-Fi 주소 고정](#wi-fi-주소-고정--ip-와-포트))
- Wi-Fi 탭에 Android 11+ 용 페어링 코드 입력 추가 (`adb pair`) — 4단계
- 같은 네트워크에서 mDNS 로 발견된 기기를 목록에 자동으로 띄우기 — 4단계, 기기로 검증 필요

### 설정 탭 — 로그 저장 카드

| 항목 | 기본값 (제안) |
|---|---|
| 새로 연결한 기기 바로 저장 | **끔** — 기기마다 카드의 ● 로 켠다. 한 번 고른 값은 다시 연결해도 유지 (2026-10-23 요청으로 '켬'에서 바꿈) |
| 저장 위치 | `문서\DroidBridge Logs` + 폴더 열기 버튼 |
| 파일 나누는 주기 | 1시간 (10분 / 30분 / 1시간 / 하루) |
| 보관 기간 | 7일 — 지나면 자동 삭제 |

```
DroidBridge Logs/
└── SM-G973N_<기기 고유번호>/        ← IP 가 바뀌어도 같은 폴더
    └── 2026-10-23/
        ├── 14-00.log
        └── 15-00.log
```

폴더 이름에 Wi-Fi 시리얼(`ip:port`)을 쓰면 안 된다. 포트가 바뀌면 같은 폰이 다른 폴더로 갈라지고,
`:` 는 Windows 파일 이름에 쓸 수 없다. 기기의 `ro.serialno` 를 쓴다.

싶으면 2단계를 가짜 데이터로 먼저 만들 수도 있다.

## 넣지 말자고 보는 것

- **여러 대 동시 미러링(멀티 화면)** — 기기마다 영상 디코딩과 전송이 붙는다. 6대면 CPU·Wi-Fi 부담이
  크고 화면도 작아져 쓸모가 떨어진다. 필요하면 카드에 1분마다 찍는 **정지 화면 썸네일**이 현실적인 대안이다.
- **기기마다 다른 저장 주기** — 설정 하나로 충분하다. 필요해지면 추가.
- **특정 앱 로그만 저장** — 크래시 원인이 시스템 로그(`ActivityManager` 등)에 남는 경우가 많다.
  전체를 저장하고 볼 때 거른다.
- **iOS** — Wi-Fi 다중 연결은 adb 방식이라 이번 범위에서 뺀다.

## 정해 주셔야 할 것

1. "설정해둔 시간마다 저장" 을 **주기마다 파일을 나눠 계속 저장**으로 이해했다. 특정 시각(예: 매일
   18시)에 한 번 저장하는 뜻이라면 설계가 달라진다.
2. 동시에 붙일 대수 — 카드 크기·열 수를 정한다 (5대 안팎 / 20대 이상).
3. 기기들의 Android 버전 — 11 이상이 섞여 있으면 페어링·포트 변경 대응이 1단계로 올라온다.
4. 저장 범위 — 기기 전체 로그(권장) / 특정 앱만.
5. 공유기 관리 권한이 있는지 — 있으면 IP 는 DHCP 예약, 없으면 폰마다 고정 IP 설정.
