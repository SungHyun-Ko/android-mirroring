# 좌측 도구 패널 활용 계획

작성 2026-09-16. UI 개편으로 기기 제어·캡처·녹화가 디바이스 툴바로 빠지면서 좌측 패널이
비었다. 무엇으로 채울지에 대한 제안이다.

## 지금 상태

| 탭 | 내용 |
|---|---|
| 미러링 | APK 설치 버튼, 화질(SD/HD/FHD), 기기 연결 |
| 파일 | PC→Android, Android→PC |
| 설정 | 미러링 기본값, 녹화 설정, 키보드 안내 |

카드 3개 남짓이라 세로 공간의 2/3가 비어 있다.

## 전제 — 이 도구를 실제로 어떻게 쓰는가

미러링 자체가 목적인 사람은 없다. QA·개발 과정에서 반복되는 건 이 고리다.

```
빌드 설치 → 앱 실행 → 재현 → 증거 수집(캡처·녹화·로그) → 티켓 작성
```

좌측 패널은 **이 고리에서 손이 자주 가는 것**을 담을 때 값어치가 생긴다. 반대로 한 번
설정하고 안 건드리는 것(비트레이트, FPS)은 설정 탭 깊숙이 있어도 된다.

---

## 1순위 — 현재 앱 작업대

지금도 LogCat 위에 현재 Activity 가 뜬다. 여기서 한 걸음 더 나가, **포그라운드 앱을
대상으로 한 작업을 한곳에 모은다.**

- 패키지명 / 버전명 / 버전코드 / 설치 시각
- 강제 종료 · 데이터 삭제 · 재실행 · 앱 정보 화면 열기
- **이 패키지만 LogCat 필터** (버튼 한 번)

**왜 1순위인가.** QA 에서 가장 자주 하는 질문이 "지금 기기에 올라간 게 몇 번 빌드냐",
가장 자주 하는 동작이 "데이터 지우고 다시 켜기"다. 지금은 둘 다 이 앱 밖에서 한다.

필요한 것: `dumpsys package <pkg>`, `pm clear`, `am force-stop`, `monkey -p <pkg> 1`.
현재 패키지는 이미 Activity 폴링으로 알고 있다.

## 2순위 — 크래시 · ANR 감지

LogCat 스트림에서 `FATAL EXCEPTION`, `ANR in`, `Force finishing activity` 를 감지해
패널에 눈에 띄게 띄우고, 해당 로그 구간을 한 번에 복사할 수 있게 한다.

**왜.** 팀에 ANR 전용 Jira 프로젝트가 따로 있을 만큼 잦은 이슈다. 지금은 수천 줄이
흐르는 LogCat 을 사람이 눈으로 훑어야 잡힌다. 이미 모든 로그가 렌더러를 지나가므로
감지 자체는 정규식 몇 줄이고, 값어치 대비 비용이 가장 낮다.

## 3순위 — 기기 정보

모델 · Android 버전 · SDK · 해상도 · 밀도 · 배터리 · 저장공간 여유.

**왜.** 티켓에 붙일 환경 정보를 매번 손으로 적는다. "전체 복사" 버튼 하나면 끝날 일이다.
`getprop` 한 번이면 대부분 나온다.

## 4순위 — 앱 목록

설치된 앱 검색 → 실행 / 강제종료 / 데이터 삭제 / 제거.

**왜 뒤인가.** 1순위(현재 앱)가 들어가면 대부분의 필요가 덮인다. 목록이 필요한 건 다른
빌드를 찾아 켤 때 정도다. `pm list packages -3` 로 서드파티만 추리면 쓸 만하다.

---

## 넣지 말자고 보는 것

- **여러 기기 동시 표시** — 미러링 파이프라인이 기기 하나를 전제로 짜여 있다. 구조를
  갈아엎는 작업인데 실제로 두 기기를 동시에 볼 일이 있는지부터 확인이 필요하다.
- **deeplink 북마크** — 있으면 편하지만 팀이 실제로 쓸지 모르겠다. 요청이 나오면 그때.
- **화질 설정(SD/HD/FHD)** — 한 번 정하면 안 건드린다. 설정 탭으로 옮기고 미러링 탭에서
  빼는 게 맞다.

---

## 제안하는 최종 구성

```
┌─ 미러링 탭 ────────────┐
│ [현재 앱]              │   패키지 · 버전                      ← 1순위
│   강제종료 데이터삭제  │
│   재실행  로그필터     │
├────────────────────────┤
│ [문제 감지]            │   크래시/ANR 발생 시에만 표시        ← 2순위
├────────────────────────┤
│ [기기]                 │   모델 · OS · 해상도 · 배터리        ← 3순위
│   정보 복사            │
├────────────────────────┤
│ APK 설치 / 기기 연결   │
└────────────────────────┘

파일 탭   — 그대로
앱 탭     — 설치된 앱 목록                                      ← 4순위
설정 탭   — 미러링 기본값 + 화질 + 녹화 + 키보드
```

## 순서에 대한 의견

1순위와 2순위는 서로 독립적이고 각각 반나절 규모다. 2순위(크래시·ANR 감지)가 **비용 대비
값어치가 가장 높다** — LogCat 스트림이 이미 렌더러를 지나가므로 붙이는 비용이 거의 없는데,
놓치면 재현을 처음부터 다시 해야 하는 종류의 정보다.

다만 이건 전부 제안이다. 실제로 QA 하면서 "이게 앱 안에 있었으면" 싶었던 게 따로 있으면
그게 1순위가 되어야 한다.
